**검색 내용** (확인됨):

## 🔍 근본 원인 분석

### 문제 1: 프롬프트 엄격성 (가장 큰 문제)

**현재 프롬프트**:
```
만약, 주어진 문맥(context) 에서 답을 찾을 수 없다면,
`주어진 정보에서 질문에 대한 정보를 찾을 수 없습니다` 라고 답하세요.
```

**문제점**:
- LLM이 **완벽한 답변**을 찾지 못하면 포기
- 부분적 정보도 제공하지 않음
- 8K 키워드가 있어도 "없다"고 답변

**증거**:
- "8K 공유" 질문: 8K 정보 O, 공유 정보 X → "없다" 답변
- "동영상 촬영" 질문: 8K 포함 답변 제공

---

### 문제 2: 복합 질문 처리 미흡

**현상**:
```
"A하고 B하는 방법" → 실패
"A하는 방법" → 성공
```

**원인**: 다중 주제를 단일 검색으로 처리

---

### 문제 3: 구체적 스펙 vs 일반 표현

**비교표**:
| 질문 유형 | 예시 | 결과 | 8K 언급 |
|-----------|------|------|---------|
| 일반 표현 | "동영상 촬영 방법" | ✅ 성공 | O |
| 구체적 스펙 | "8K 촬영 방법" | ❌ 실패 | X |
| 사실 확인 | "최대 해상도?" | ✅ 성공 | O |

**원인**: 임베딩 모델의 특정 기술 용어 인식 한계

## 💡 개선 방안

### 🔴 즉시 적용 (1시간 내)

#### 1. 프롬프트 개선
```python
# main.py의 _create_prompt_template 수정

template = """당신은 질문-답변을 수행하는 AI 어시스턴트입니다.

주어진 문맥을 사용하여 질문에 답하세요.

답변 규칙:
1. 문맥에 완전한 답변이 있으면 상세히 답변하세요.
2. 부분적 정보만 있다면:
   - 답할 수 있는 부분을 제공하고
   - "단, [부족한 부분]에 대한 정보는 문서에 없습니다"라고 명시하세요.
3. 전혀 관련 정보가 없다면:
   - "주어진 정보에서 질문에 대한 정보를 찾을 수 없습니다"라고 답하세요.
4. 추측하지 말고 문맥에 있는 내용만 답변하세요.
5. 기술 용어는 원문 그대로 사용하세요.

#Question:
{question}

#Context:
{context}

#Answer:"""
```

**예상 효과**: 부분 답변 가능, 성공률 50% → 70%

## 🎓 핵심 교훈

### 1. 일반적 질문 > 구체적 질문
- "동영상 촬영 방법" → 8K 정보 포함 ✅
- "8K 촬영 방법" → 실패 ❌
- **교훈**: 현재 시스템은 일반적 질문에 더 적합

### 2. 검색 성공 ≠ 답변 성공
- 8K 키워드 검색됨 → 하지만 답변 실패
- **교훈**: LLM 프롬프트 설계가 중요

### 3. 부분 답변의 중요성
- 완벽한 답변 못 찾으면 포기 → 비효율적
- **교훈**: 부분 답변 허용이 사용자 경험 향상
